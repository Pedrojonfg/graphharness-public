# Research Brief: Pedagogical TikZ + code-comprehension exercises
**Depth**: wide (+ deep on decision points)
**Date**: 2026-11-12
**Research time**: ~1 session

## Executive Summary

Today the Hub **does use TikZ**, but only as a concept map in report PDFs: it is generated by deterministic code (`graphTikz`), not by an agent, and there is no MCP tool or prompt for didactic figures. The biggest jump in value for math is a pipeline "LLM drafts TikZ → Hub compiles/validates → SVG in the PWA / PDF in the report", with templates per family (geometry, axes, Venn, trees, flows) and a *teaching* mode. For programming, the current stack (SymPy recipes + cloze/text/mcq cards) is no use for studying code; what research and edtech show to be useful —Parsons, faded Parsons, predict/trace, spot-the-bug— fits the Hub's golden rule very well (code grades; the LLM drafts) and should come in first as **new card `kind`s** and then as exercise templates/`eval`.

| Product / pattern | Strengths | Weaknesses | Pricing / access | Users / signal |
|---|---|---|---|---|
| **OpenTikZ** (skill + library) | Reusable templates, compiles standalone, fixed palette, PNG→TikZ | Focused on ML/CS papers rather than math pedagogy | MIT / CC0 | Claude Code agents |

| **tikz-scientific-figures** (PM-Shawn) | Broad coverage (pgfplots, circuitikz, commutative diagrams…) | An agent skill, not a study product | Open source | Research figures |
| **TeachForge TikZ Station** | Live SVG preview, classroom templates, human in the loop | A SaaS for teachers, no domain graph | Commercial | Teachers |
| **YouLearn** | Live LaTeX notebook + TikZ in "explainers" | Hackathon project; no mastery tracking | OSS | Students |
| **LaTeX2SVG / similar** | Fragment → vector SVG for the web | Not an LMS; render only | Free / self-host | Web STEM |
| **Runestone / Codio / js-parsons** | Parsons + adaptive + distractors; empirical evidence | Do not integrate a concept graph or SM-2 | Education platforms | CS1 |
| **EvoParsons** | Evolutionary generation of informative puzzles | Intro Java/C; not generic modern Python | Free OSS | Novices |
| **Python Tutor** | Visual mental model of execution | Does not auto-grade on its own (except tracing forks) | Free | Millions |

### Key Insights

1. **Agents are already good at TikZ** if the flow is: template/family → draft → **compile** → look at the output → iterate. Without the compile + QA step, "raw" TikZ often fails (packages, overlaps, wrong geometry).
2. **Teaching mode** (pedagogical labels in the figure) vs **research** mode (clean) is a recurring pattern: for Pedro-the-student, teaching by default makes sense.
3. **KaTeX does not replace TikZ**: the Hub already renders `$…$` in HTML cards/reports; TikZ adds *diagrams* (axes, triangles, semantic graphs, Venn diagrams, algorithm flows).
4. In CS education, **ordering/completing code** beats memorizing syntax and is as effective as writing from scratch, in less time (Ericson et al.). That matches your intuition: pure syntax is already "done" by the guide.

## Ecosystem Signals

### Most Popular Plugins / Add-ons (signal of need)

**TikZ / figures**
- Libraries most requested in STEM education: `pgfplots`, labeled geometry, `tikz-cd`, trees (`forest`), Venn, free-body / vectors, circuitikz.
- Agent skills: OpenTikZ (edit template + verify), Patrick-Healy (visual QA + teaching mode).

**Programming**
- Parsons with distractors and adaptation (Runestone "Help Me").
- Faded Parsons (blanks in lines + ordering) for patterns.
- Tracing / "what does this print?" and spot-the-bug as a reading→writing bridge.

### Most Requested Features (demand)

- Figures that **compile on the first try** and can be **re-edited** (not an opaque PNG).
- **SVG** preview on screens (not just PDF).
- Code exercises **without fighting the language's compiler** (Parsons reduces cognitive load).
- Immediate, local feedback (no waiting for an LLM judge).

### Integration Patterns

- An agent skill **outside** the product + a local TeX toolchain.
- The product educates: AI draft → **human approval** → SVG/PDF to the student (TeachForge).
- A LaTeX notebook that the agent maintains (YouLearn).
- In graphharness the natural analogue is: the **Hub's MCP** as the real toolchain (compile, save asset, attach to concept/card/explanation), not just a loose skill on the laptop.

## Technical Landscape

| Decision | Options | Recommendation | Why |
|---|---|---|---|
| Who generates TikZ? | External skill only / Hub MCP / worker job | **Hub MCP (+ a skill that invokes it)** | Same security rules and quotas; the asset stays in the domain |
| Web rendering? | PDF embed / PNG / SVG / KaTeX-only | **SVG** (pdflatex → pdf → `pdftocairo`/`dvisvgm`) | Crisp in the PWA; consistent with LaTeX2SVG |
| Figure QA? | Just "compiles" / + LLM vision / + rules | **Compiles + static checklist** (size, forbidden cmds, `\begin{tikzpicture}`); vision optional later | The Hub already lives on deterministic verifiers |
| Animation? | Manim / animate.sty / nothing | **Nothing in figures V1**; Manim separately if you want video | High cost; static TikZ gives 80 % of the value in cards/reports |
| Parsons grader | js-parsons / own / Runestone | **Own order grader (+ optional indent)** in Hub/core | Avoids AGPL/heaviness; simple contract |
| Execute student code | Docker / pyodide / do not execute | **Do not execute** at first; only order/expected output/MCQ | Aligned with eval's current sandbox |
| Subject kind | `general` / new `programming` | **`programming`** (or `computable_code`) | Separates SymPy templates from code templates |

## Proposed Architecture

### A) Didactic TikZ figures

```
Agent / LLM job
    │  TikZ draft (family + teaching mode)
    ▼
MCP compile_tikz_fragment { tex, libraries[] }
    │  standalone wrap + whitelist libs + FORBIDDEN_TEX
    ▼
pdflatex (existing sandbox) ──fail──▶ structured error to the agent (retry)
    │ ok
    ▼
pdf → svg/png  →  figures/ (or blob in sqlite)  →  attach(conceptId|cardId|reportSection)
    ▼
PWA: <img src=…> / PDF report: \includegraphics or inline fragment
```

**Files to touch / create**

| Area | Files | Change |
|---|---|---|
| Latex core | `packages/latex/src/fragment.ts` (**new**), `compile.ts`, `escape.ts`, `types.ts` | Standalone wrapper, whitelist of `\usetikzlibrary` / packages (`pgfplots`…), `compileFragment` → `{pdf,svg?,log}` |
| TeX templates | `packages/latex/templates/fragment.tex` (**new**) | Minimal crop-friendly document |
| Contracts | `packages/contracts/src/mcp.ts`, OpenAPI | Tools `compile_tikz_fragment`, `save_figure`, `list_figure_templates` |
| Hub | `apps/hub/src/services/figures.ts` (**new**), MCP handlers, SQL migration `figures` | Persistence + permissions |
| Deploy | `docs/DEPLOY.md`, CI, `.env.example` | `pdftocairo`/`dvisvgm`; extra TeX libs |
| Prompts | `packages/llm/prompts/figure-generate.v1.md` (**new**); extend `exercise-explain`, `cards-generate`, `report-session`, `template-generate` | Ask for an optional figure; explain: diagram *in addition to* formulas |
| PWA | `apps/pwa` (Cards, Exercises, concept detail) | Render SVG; no KaTeX for TikZ |
| LH fork | `src/agent/prompts/teacher/90-*.md`, practice | "If the concept has a figure, use it; do not invent TikZ in the chat — ask the Hub" |

**Prompts — what to change concretely**

1. **New** `figure-generate.v1.md`: allowed families, teaching mode, only `\begin{tikzpicture}…\end{tikzpicture}`, no `\documentclass`, labels in Spanish, explicit coordinates, "do not use libraries outside the list".
2. **`exercise-explain.v1.md`**: allow an optional `diagramHint` field or an attached already-compiled `figureId`; **still** no raw TikZ from the LLM in the steps JSON (avoids failures); the worker/Hub generates or reuses a figure.
3. **`cards-generate.v1.md`**: an optional new kind later (`figure_cloze`: "name the marked element") or a `figureId` field on the front.
4. **`template-generate.v1.md`**: optional `methodFigure` (description → figure job).
5. **LH `90-hub-*`**: the teacher describes *what* to draw or picks a template; it does not paste long TikZ blocks in the chat.

**Suggested TikZ phases**

1. **P0 — Fragment toolchain**: `compileFragment` + SVG + test; no UI.
2. **P1 — MCP + skill**: Pedro's agent can create/save figures on a concept.
3. **P2 — Explainer + reports**: method figure in the master PDF; explain shows SVG.
4. **P3 — Cards with a figure**: cloze/mcq over a diagram.
5. **P4 — Classroom template library** (IE/course math): triangle, 2D axes, Venn, small graph, decision-tree diagram.

### B) Programming comprehension (not pure syntax)

**Recommended taxonomy (value / effort order)**

| Type | What it practices | Grading | Where it fits |
|---|---|---|---|
| **Parsons** (order lines) | Flow, structure | Permutation + optional indent | Cards + exercises |
| **Parsons + distractors** | Discriminating typical bugs | Order ⊂ lines; junk to the trash | Exercises |
| **Faded Parsons** | Patterns (blanks + order) | Order + `normalizeAnswer` on blanks | Exercises |
| **Predict / trace** | Mental model | Exact output or MCQ | Cards (fast) |
| **Spot the bug** | Critical reading | Line index / option | Cards |
| **Fix one line** | Minimal debugging | One-line diff or test | Later |
| **Python Tutor embed** | Deep visualization | No grading or manual grading | LH session |

**Architecture aligned with the golden rule**

```
LLM (cards-generate / template-generate)
    → JSON: shuffled lines, correct order, distractors, expected output
Hub validates schema
Interactive PWA/LH UI
Deterministic grader (core or eval)
Evidence: flashcard | hub_exercise (same weights)
```

**Why cards first**

- 100 % local grading.
- SM-2 already exists.
- Simpler UI than a full exercise.
- Fits "comprehension micro-practice" between LH sessions.

**Why exercises afterwards**

- Distractors + faded + `hub_exercise` evidence with `missClass`.
- Reuses the LH dock (ADR 107): the model does not see the solution.

## Risks and Open Questions

1. **LLM TikZ is still fragile** without templates: mitigate with fixed families and retries with the pdflatex log (as you already do with formulas).
2. **SVG on ARM/VPS**: verify `pdftocairo`/`dvisvgm` in the same `[VERIFY]` checklist as DEPLOY.
3. **Extra TeX libraries** increase image/deps; strict whitelist.
4. **Parsons with several valid solutions**: atomic blocks or a dependency graph have to be enforced (Runestone); otherwise false negatives.
5. **Execute code?** It opens security surface; delaying it is right.
6. **Manim vs TikZ**: do not compete; TikZ = static in the product; Manim = long content/video outside the card loop.
7. **V3 scope**: ADR 105 does not contemplate this; an ADR of its own would be needed before large migrations.
